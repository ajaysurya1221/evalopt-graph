## Source findings

1. **No whole-fragment bypass from the proposed entries.** In `detect_detect.go:767–815`, AND entries containing a nonempty `Regexes` array execute `continue` at lines 792–793 before the fragment-level `allTrue` call. This applies both to the global call at line 302 and the rule call at line 388. Adding a commit list does not remove that deferral. At finding time, lines 849–866 require commit, path and regex checks together. The proposed entries therefore exempt matching findings, not an entire commit, file or line. This statement is limited to these entries; other existing/native exceptions retain their independent semantics.

2. **Empty commit metadata fails closed for each proposed entry.** `config_allowlist.go:117–133` returns false immediately for an empty supplied commit. Because a proposed entry has a nonempty commit list, `detect_detect.go:851–854` includes that false result in its AND. A matching path and captured value cannot overcome it. An empty configured `commits` list would instead omit the check, so a structural assertion that the exact expected nonempty list is present is essential. A global fallback entry without commits must not be added.

3. **Commit matching is exact, case-normalized membership, not a prefix.** Validation trims and lowercases configured values at `config_allowlist.go:84–92`; lookup lowercases the supplied commit at 122. The native parser does not enforce full SHA syntax. The run's control must enforce a one-element list containing the exact expected 40 lowercase hexadecimal characters. Incorrect or truncated nonempty values become inert; absence of the entire criterion is a widening.

4. **Target rules remain stock.** `config_config.go:228–242` excludes targeted entries from the global allowlist. Lines 269–277 append them only to named existing rules after extension, rejecting an unknown rule ID. With no rule definition or overrides, the proposed entries do not replace stock regexes, groups or entropy checks. Require `useDefault = true` and preserve the existing synthetic OpenAI fixture entry unchanged.

5. **The value target is each extracted secret.** `detect_detect.go:452–567` creates and evaluates each finding separately, extracting its configured secret group before calling the allowlist. `regexTarget = "secret"` is normalized to the default secret target (`config_config.go:329–338`); `line` would instead inspect shared line content and is unsuitable here. Exact path/value anchors remain necessary because the lists are regexes, internally OR, rather than literal equality tests.

The five group assignments remain: H4 → generic-api-key / V4 / V4M or V4R; HN and HO → generic-api-key / V1M / V1C or V1S; D → generic-api-key / V1P / V1P; T → github-pat / V4 / V4C. ## Corrections to the consultation and proof limits

- An **omitted** condition defaults to OR, but an **invalid condition value** does not: `config_config.go:320–326` returns a load error. A misspelled configuration key could leave the recognized condition empty; that is different from an invalid value. The opinion's blanket statement that a misspelled condition parses as OR should not be copied into the implementation report.
- Fresh-commit negative controls **cannot by themselves detect deletion of the regex criterion**. The commit check is already false, so even an accidentally commit-and-path-only AND entry will leave those new findings visible. This corrects the claim in the opinion's N1. A control with a matching commit and path, but a distinct detected secret, is indispensable to prove that a whole-fragment bypass was not introduced.
- Removing commit clauses in a derived test configuration can isolate path/value behavior, but it does not replace a native test of the shipped configuration with empty commit metadata. A bare stdin test can fail because it lacks a path as well; use dir mode with the exact known path to isolate missing commit metadata.
- A 17→0 comparison is complete for the retained immutable public refs, scanner/configuration and git-log/decoding scope actually exercised. It is not a universal proof for altered scan flags, future scanner versions or other detection contexts. There are no line/column selectors in the proposed clauses; coordinates belong in the observed roster comparison. Commit pinning prevents matching later commits, but does not justify an unlimited claim about all future scan behavior.
