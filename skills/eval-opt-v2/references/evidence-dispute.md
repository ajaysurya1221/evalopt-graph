# Typed evidence and dispute procedure

Use this procedure only when evidence or a check conflicts with the task contract
or a proposed claim. It consumes the existing task budget.

1. Bind the relevant observation to the candidate and command. Separate execution
   state and exit code from evidence availability and from the claim being made.
   Identify precisely which fact supports, contradicts, or leaves that claim open.
2. Check the disputed behavior against the visible contract. Seek the smallest
   permitted counterexample, including the trigger and expected versus observed
   behavior. For a review, compare baseline and candidate; distinguish one cause
   with several supported effects from unrelated or invented findings.
3. Retain the failed check and supporting artifact. Report the disagreement and
   its evidence in the task's response format. Do not edit a frozen check, relabel
   its outcome as passed, waive a requirement, or self-certify a disputed claim.
4. Choose the next authorized action from the contract: repair the candidate when
   it is wrong, continue a permitted investigation, or state the unresolved gap.
   A supported blocker completes only a task whose requested outcome is that
   blocker report. It cannot substitute for a solvable implementation.

Disagreement alone is not success. A wrong agent and a wrong check both require
evidence; preserve uncertainty when the counterexample cannot be verified.
