# evalopt v0.1.1 — Final deprecation release

Standalone feature development has ended. This release preserves the acceptance kernel and its
research record, adds migration guidance, and closes new feature and integration intake. For new
systems, start with the [alternatives and migration map](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/docs/migration.md).

Evalopt evaluates supplied evidence against policy; it is not a semantic truth oracle. Its ten
stable exports, five terminal states, serialization, reason codes, replay and fail-closed decisions
remain in place. Required runtime dependencies remain empty. Deprecated host surfaces remain in the
distribution but receive no feature work. Repository archival is a separate human action, not a
status claimed by these notes. The [public release record](https://github.com/ajaysurya1221/evalopt-graph/releases/tag/v0.1.1)
establishes publication status and date; a copy of these notes alone does not.

## What changed

The wind-down preserves the implementation at verified main
[`fc3045d`](https://github.com/ajaysurya1221/evalopt-graph/tree/fc3045dbda29c1d274747329ceb6724a783b0df7),
except the package version literal. It adds the STOP decision, a sixteen-entry migration map,
source and coverage appendices, a portfolio index, and bounded contribution and security guidance.
The migration map documents analogies and non-equivalence; it supplies no converter or new standard.

This is **not** a claim of byte-identical behavior to v0.1.0. The final distribution also contains
changes already merged between the v0.1.0 tag and that main baseline:

1. `AcceptanceInput` rejects scalar string/bytes and non-iterable acceptance-row inputs with
   `ValueError`; `from_dict` uses the same validation. Credit to Göktuğ Özkan
   ([@goktugozkanmd](https://github.com/goktugozkanmd)) for
   [PR #4](https://github.com/ajaysurya1221/evalopt-graph/pull/4), commit `624ed11`.
2. The compatibility host's detected Python test command uses the quoted running interpreter,
   `sys.executable`, rather than bare `python`. Compatibility warnings and documentation point to
   external overnight helpers and the external Claude skill.
3. The build pin, optional provider/development dependency floors and their lock entries changed
   before the wind-down. Core metadata is pinned to 2.4. Overnight helper assets moved outside the
   package and are excluded from the source distribution. See the [changelog](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/CHANGELOG.md)
   for the exact inherited versions and other earlier documentation changes.

Release identities and current install instructions move to 0.1.1. The scanner retains stock rules
and full-history scanning; the reviewed nonsecret history exceptions require an exact historical
commit, path, rule and captured value together. Release protections and action pins are unchanged.
No runtime warning, new API, predicate, adapter, integration or benchmark was added by the wind-down.

## Existing users

Existing records retain the semantics and limits of the version that produced them. Preserve the
policy, input, decision, version and host evidence when migrating. A content hash does not
authenticate a producer, and a signed statement does not establish semantic correctness. No
destination is promised to preserve evalopt's terminal states or reason codes automatically.

The [migration map](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/docs/migration.md), [coverage roster](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/docs/migration-coverage.md) and
[portfolio index](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/docs/portfolio.md) give the routes and limits. The v1–v4 research branches, results,
frozen sources, old tags and assets remain preserved separately; they are not merged into this
release and are not new comparative evidence for it.

## Install and verify published artifacts

Use the public release record to confirm availability, then install in an isolated environment:

```bash
python -m pip install evalopt-graph==0.1.1
```

Python 3.10–3.14 remains supported. After downloading the wheel, source distribution and evidence
assets from the release, check the distribution checksums and both GitHub attestations:

```bash
shasum -a 256 -c SHA256SUMS.txt
gh attestation verify evalopt_graph-0.1.1-py3-none-any.whl \
  --repo ajaysurya1221/evalopt-graph \
  --signer-workflow ajaysurya1221/evalopt-graph/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.1 --deny-self-hosted-runners
gh attestation verify evalopt_graph-0.1.1.tar.gz \
  --repo ajaysurya1221/evalopt-graph \
  --signer-workflow ajaysurya1221/evalopt-graph/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.1 --deny-self-hosted-runners
```

Attestation verification authenticates the named workflow's provenance assertion; it does not
prove functional correctness or production safety. The SPDX asset inventories the two distribution
archives, not every source file or optional dependency. Local candidate checks, hosted artifact
checks and actual publication are distinct evidence stages in the final release receipt.

## Maintenance

Bug reports with a version and minimal reproduction, documentation corrections and private security
reports remain available under [CONTRIBUTING](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/CONTRIBUTING.md) and
[SECURITY](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/SECURITY.md). A final deprecation release does not rule out a later security patch;
no support period or response capacity is promised. No new standalone features or shared portfolio
runtime layer are planned. See the [STOP decision](https://github.com/ajaysurya1221/evalopt-graph/blob/v0.1.1/docs/decisions/archive-standalone.md) for the
reopening conditions and the human-owned archival step.
